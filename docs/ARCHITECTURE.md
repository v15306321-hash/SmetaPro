# Архитектура

```
 Telegram ──► aiogram (app/bot) ─┐
                                 ├─► app/services/*  ──►  SQLAlchemy  ──►  PostgreSQL
 Браузер  ──► FastAPI (app/web) ─┘        │
                                          ├─► app/pdf (ReportLab) ──► stored_files в БД (PDF, чеки, логотипы)
                                          └─► notifications (таблица-очередь) ──► воркер бота ──► Telegram
```

## Принципы

1. **Одна бизнес-логика.** Обработчики бота и маршруты сайта не содержат правил: они вызывают функции
   `app/services/*`. Пример: `estimates.generate(ctx, order_id)` вызывается и кнопкой «📄 PDF-смета» в боте,
   и может быть вызвана из веб-модуля — проверки прав, тарифа и лимита выполняются внутри.
2. **Контекст доступа `Ctx`** (`services/accounts.py`): пользователь + активное предприятие + роль + набор прав.
   Каждый сервис первым делом вызывает `ctx.require("право")` и/или `tariffs.require_feature(...)`.
3. **Изоляция предприятий.** Все выборки фильтруются по `enterprise_id` из `Ctx`, а не из пользовательского ввода.
   Объекты по id загружаются через функции `get(ctx, id)`, которые возвращают «не найдено» для чужих данных.
   Покрыто тестами (`test_tenant_isolation`, `test_full_web_flow`).
4. **Тарифы — данные, а не код.** Цены, лимиты и флаги функций хранятся в таблице `plans` и редактируются в
   админ-панели. Код проверяет флаги (`analytics`, `pdf_logo`, `expenses`, `waste`, `order_statuses`,
   `custom_markups`), а не названия тарифов.
5. **Деньги и идемпотентность.** Подтверждение оплаты — условный `UPDATE ... WHERE status='pending'`;
   повторное нажатие или два администратора одновременно не создадут вторую подписку (тест
   `test_concurrent_approval_activates_once`, проверен на PostgreSQL). Списание лимита смет — также атомарное.
   Telegram-апдейты дедуплицируются по `update_id` (таблица `processed_updates`).
6. **Журналирование.** Действия с деньгами, доступом, тарифами и бонусами пишутся в `audit_log`
   (просмотр — «Журнал» в админ-панели). Секреты и содержимое файлов не логируются.

## Модули сервисного слоя

| Модуль | Ответственность |
|---|---|
| `accounts` | пользователи Telegram, регистрация предприятия, контекст доступа, наценки, логотип, блокировки |
| `tariffs` | тарифы, текущая подписка, активация/продление/смена, проверка функций и лимитов |
| `payments` | заявки на оплату, чек, подтверждение/отклонение/возврат, реквизиты |
| `referrals` | реферальные связи, скидка 10–50 %, одноразовое использование, аннулирование |
| `crypto_pay` | заготовка CRYPTO PAY: инвойс, проверка подписи webhook (сценарий — после получения API) |
| `materials` | база материалов/фурнитуры, лимиты, архивирование используемых позиций |
| `orders` | заказы, калькулятор, наценки заказа, статусы и их история |
| `estimates` | генерация PDF, списание лимита, уведомления о лимите |
| `expenses` | производственные затраты, категории (без «Сборки» и «Монтажа») |
| `waste` | плановый/фактический расход, отходы, отклонения |
| `analytics` | показатели за период, ряды для графиков |
| `staff` | приглашения, роли, права администратора, лимит пользователей |
| `auth_web` | вход на сайт через бота / Telegram Login Widget, веб-сессии, отзыв |
| `admin` | статистика платформы, поиск, редактирование тарифов, ручная активация |
| `jobs` | напоминания об окончании подписки, очистка |
| `audit` | журнал и очередь уведомлений |

## Роли и права

Матрица в `app/core/permissions.py` (одно место). Владелец — все права. Администратор — набор прав, выданный
владельцем в кабинете (кроме оплаты подписки и управления сотрудниками — только владелец). Мастер — заказы
(просмотр, статусы), расход/отходы, производственные затраты. Менеджер — заказы, сметы, просмотр материалов.
Детализация ролей — предмет согласования (см. OPEN_QUESTIONS.md).

## Вход на сайт

Основной способ — подтверждение в боте: сайт создаёт одноразовый запрос (токен для бота + секрет опроса,
известный только браузеру), бот по deep-link `login_<token>` показывает кнопку «Подтвердить», браузер
получает сессию. Альтернатива — официальный Telegram Login Widget (подпись проверяется на сервере
HMAC-SHA256 от токена бота). Веб-сессии хранятся в БД (в cookie — случайный токен, в БД — его SHA-256),
список активных сессий и отзыв — в «Профиле». Формы защищены CSRF-токеном, cookie — `HttpOnly`, `SameSite=Lax`,
`Secure` в production.

## Файлы

PDF-сметы, чеки и логотипы хранятся в таблице `stored_files` (а не на диске): они переживают перезапуски на
хостингах с временной файловой системой (Render Free) и попадают в резервные копии БД. Доступ к файлу
проверяет принадлежность предприятию. Смета ≈ 50 КБ.

## Уведомления

Сервисы пишут уведомления в таблицу `notifications` (с `dedup_key`, чтобы не дублировать). Фоновая задача
доставляет их сразу после действия пользователя (сигнал `kick()` после каждого POST-запроса и апдейта
Telegram), а не опросом базы — поэтому бесплатная БД Neon может засыпать при простое; ошибки доставки повторяются до 5 раз, заблокировавшие бота
пользователи помечаются. Раз в `JOBS_INTERVAL_SECONDS` (600 с; на бесплатном варианте — 3600 с) выполняются напоминания об окончании подписки (за 3 дня и 1 день)
и уведомления об истечении.

## Безопасность (ТЗ п. 19)

- Секреты только в переменных окружения (`.env.example` без значений); `SECRET_KEY` и запрет `DEV_LOGIN`
  проверяются при старте в production.
- Проверка прав на сервере для каждого действия; изоляция предприятий.
- Ограничение частоты запросов (в приложении и рекомендованное в nginx).
- Загружаемые файлы: проверка размера (8 МБ) и типа по сигнатуре содержимого, случайные имена, запрет выхода
  за пределы каталога хранилища.
- Внутренние ошибки не показываются пользователю (общие сообщения, трассировка — в логах сервера).
- Заголовки безопасности (`X-Frame-Options`, `nosniff`, HSTS в production).

## Ограничения текущей версии

- FSM-состояния бота хранятся в памяти процесса: при перезапуске незавершённый диалог сбрасывается (данные не
  теряются). Для нескольких экземпляров бота — подключить `RedisStorage` aiogram.
- Встроенное ограничение частоты запросов работает в пределах одного процесса — для масштабирования
  использовать nginx/Redis.
- Создание и редактирование заказов, смет и базы материалов на сайте не входит в первую версию (ТЗ 3.2) —
  в кабинете заказы и сметы доступны для просмотра и скачивания; API и сервисы готовы для веб-модулей.
