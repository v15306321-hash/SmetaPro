# Развёртывание на Render — пошаговая инструкция

От нуля до работающих сайта и бота. Время — около 30 минут. Программировать не нужно.

## Что получится

```
Render
├── furniture-db            PostgreSQL — все данные (пользователи, заказы, платежи…)
└── furniture-estimate      веб-сервис: сайт + кабинет + админка + Telegram-бот + фоновые задачи
    └── диск 1 ГБ           PDF-сметы, чеки, логотипы
```

Бот работает внутри веб-сервиса через webhook, поэтому отдельный сервер для него не нужен.

## Стоимость (проверьте на render.com/pricing)

| Что | План | ≈ в месяц |
|---|---|---|
| Веб-сервис | Starter | $7 |
| Диск 1 ГБ | — | $0,25 |
| База данных | Basic-256mb | $6 |
| **Итого** | | **≈ $13–14** |

Почему не бесплатно:
- **Бесплатный веб-сервис** засыпает через 15 минут без посещений. Бот в это время не отправляет уведомления, а первое сообщение после сна ждёт ответа до минуты. Кроме того, к бесплатному сервису нельзя подключить диск: сметы и чеки будут пропадать при каждом обновлении.
- **Бесплатная база** удаляется через 30 дней.

## Шаг 1. Создайте бота в Telegram

1. Откройте в Telegram **@BotFather** и отправьте `/newbot`.
2. Введите название, например `Furniture Estimate`.
3. Введите имя пользователя, оно должно заканчиваться на `bot`, например `FurnitureEstimateUzBot`.
4. BotFather пришлёт **токен** вида `7123456789:AAH...`. Скопируйте его и **никому не пересылайте**.
5. Запишите имя бота без `@`, это будет `BOT_USERNAME`.

## Шаг 2. Узнайте свой Telegram ID

Откройте **@userinfobot** и нажмите «Start». Он пришлёт ваш **Id** — число вида `123456789`.
Это `SUPERADMIN_TELEGRAM_IDS`: с этим ID вы будете администратором платформы и сможете подтверждать оплаты.
Если администраторов несколько, перечислите их ID через запятую: `123456789,987654321`.

## Шаг 3. Подготовьте репозиторий на GitHub

Render берёт код из ветки `main`. Сейчас код лежит в ветке `claude/keen-lovelace-aqh7hj`.

1. Откройте https://github.com/v15306321-hash/SmetaPro/branches
2. Напротив ветки `claude/keen-lovelace-aqh7hj` нажмите ✏️ (Rename branch).
3. Введите `main` и нажмите **Rename branch**.

> Другой вариант — попросите меня перенести код в `main`.

## Шаг 4. Зарегистрируйтесь на Render

1. Откройте https://render.com и нажмите **Get Started**.
2. Войдите через **GitHub** — так проще всего подключить репозиторий.
3. Добавьте банковскую карту: **Account Settings → Billing**. Без неё платные планы не создаются.

## Шаг 5. Создайте всё одной кнопкой (Blueprint)

В репозитории есть файл `render.yaml`: в нём описаны база, сервис, диск и настройки.

1. В Render нажмите **New + → Blueprint**.
2. Нажмите **Connect GitHub** и дайте доступ к репозиторию `SmetaPro`. Можно выбрать «Only select repositories».
3. Выберите репозиторий **SmetaPro** и ветку **main**.
4. Укажите **Blueprint Name**, например `furniture-estimate`.
5. Render покажет, что будет создано: `furniture-db` и `furniture-estimate`. Ниже он попросит заполнить переменные:

| Переменная | Что вписать |
|---|---|
| `BASE_URL` | `https://furniture-estimate.onrender.com` (точный адрес проверим в шаге 6) |
| `BOT_TOKEN` | токен из шага 1 |
| `BOT_USERNAME` | имя бота без `@` |
| `SUPERADMIN_TELEGRAM_IDS` | ваш ID из шага 2 |
| `SUPPORT_TELEGRAM` | контакт поддержки для сайта, например `@your_support` (можно оставить пустым) |

6. Нажмите **Apply**.

`SECRET_KEY` и пароль базы Render создаст сам — вводить их не нужно.

Первый запуск занимает 5–10 минут. Порядок такой: создаётся база → устанавливаются зависимости → создаются таблицы → запускается сервис.

## Шаг 6. Проверьте адрес сайта

1. Откройте **Dashboard → furniture-estimate**.
2. Под названием сервиса будет его адрес, например `https://furniture-estimate.onrender.com`.
   Если имя было занято, Render добавит к нему окончание, например `furniture-estimate-a1b2.onrender.com`.
3. Если адрес **отличается** от того, что вы вписали в `BASE_URL`:
   - откройте **Environment**, исправьте `BASE_URL` на точный адрес (с `https://`, без `/` в конце);
   - нажмите **Save, rebuild, and deploy**.

`BASE_URL` должен совпадать с адресом точно: по нему бот регистрирует webhook, и Telegram отправляет сообщения именно туда.

## Шаг 7. Убедитесь, что всё работает

1. **Логи:** сервис → вкладка **Logs**. В них должно быть:
   ```
   Telegram webhook set: https://.../telegram/webhook
   Application startup complete.
   ```
   Если там `Не удалось установить webhook` — проверьте `BOT_TOKEN` и `BASE_URL` (раздел «Если что-то не так»).
2. **Сайт:** откройте адрес сервиса — должна загрузиться главная страница.
3. **Бот:** откройте своего бота в Telegram и отправьте `/start`. Он предложит зарегистрировать предприятие.
4. **Администрирование:** отправьте боту `/admin` — появится сводка платформы.
5. **Вход на сайт:** нажмите на сайте «Войти» → «Войти через Telegram» → в боте «✅ Подтвердить вход». Откроется кабинет; ссылка «Админ-панель» внизу меню видна только администраторам.

## Шаг 8. Проверьте реквизиты и тарифы

Сайт → **Админ-панель → Тарифы и реквизиты**.

- Номера карт HUMO, CLICK и UZUM BANK уже заполнены значениями из ТЗ. Проверьте их и при необходимости укажите получателя.
- Цены и лимиты тарифов соответствуют ТЗ. Их можно менять здесь же, без программиста.

## Шаг 9. Пройдите сценарий от начала до конца

1. В боте: «💳 Подписка» → START → HUMO → отправьте любое фото как чек.
2. Вам как администратору придёт уведомление. Откройте `/admin` → «✅ Подтвердить».
3. «⚙️ Настройки» → «📐 Наценки» → например `30 20 10 0`.
4. «📦 Материалы» → «➕ Добавить материал».
5. «🧮 Новый расчёт» → добавьте позиции → «📄 PDF-смета».
6. В кабинете на сайте появятся заказ, смета и (с BUSINESS) аналитика.

Тестовые данные можно оставить. Тестовую подписку можно прекратить: «Админ-панель → Заявки → Подтверждённые → Отметить возврат».

## Свой домен (по желанию)

1. Сервис → **Settings → Custom Domains → Add Custom Domain**, введите `example.uz` и `www.example.uz`.
2. У регистратора домена добавьте DNS-записи, которые покажет Render (обычно `CNAME` для `www` и `A`/`ALIAS` для корня).
3. Дождитесь статуса **Verified** — сертификат HTTPS Render выпустит сам.
4. Поменяйте `BASE_URL` на `https://example.uz` → **Save, rebuild, and deploy**. Бот сам перерегистрирует webhook.
5. Для кнопки Telegram Login Widget на странице входа (необязательно): в @BotFather `/setdomain` → выберите бота → `example.uz`. Затем в Environment добавьте `TELEGRAM_LOGIN_WIDGET=true`.

## Резервные копии

- **База:** на платных планах Render делает ежедневные бэкапы. Посмотреть их можно в **furniture-db → Recovery**.
- **Диск:** Render делает ежедневные снимки диска. Посмотреть их можно в **furniture-estimate → Disks**.
- Дополнительная ручная копия базы: **furniture-db → Info**, скопируйте *External Database URL* и выполните на своём компьютере:
  ```bash
  pg_dump "<External Database URL>" -Fc -f furniture-backup.dump
  ```

## Обновления

Включено автоматическое развёртывание: любое изменение в ветке `main` → Render сам пересоберёт и перезапустит сервис.
Перед запуском он применит миграции базы. На время перезапуска сайт и бот недоступны около минуты: это особенность сервисов с диском. Сообщения в Telegram за это время не теряются — Telegram доставит их после запуска.

## Если что-то не так

| Симптом | Причина и решение |
|---|---|
| Бот не отвечает на `/start` | В Logs нет строки `Telegram webhook set` → проверьте `BOT_TOKEN` (без пробелов) и `BASE_URL` (с `https://`, точный адрес). Исправьте → **Save, rebuild, and deploy** |
| `Не удалось установить webhook` в логах | Неверный токен, или `BASE_URL` указывает не на этот сервис |
| `/admin` → «Доступ только для администраторов» | Ваш ID не указан в `SUPERADMIN_TELEGRAM_IDS`, или указан с ошибкой |
| Деплой упал на шаге *Pre-Deploy* | Logs → Deploy → смотрите ошибку миграции; база должна быть в статусе *Available* |
| После входа на сайте снова просит войти | `BASE_URL` начинается с `http://` вместо `https://` |
| `RuntimeError: SECRET_KEY must be set` | Переменная `SECRET_KEY` удалена — в Environment нажмите **Generate** |

Если не получается — пришлите текст из вкладки **Logs**, токен присылать не нужно.
